# RDK Candle — свічки з малюнком на склі

Сайт українського виробника свічок. Має два розділи:

- **Магазин (головна сторінка)** — каталог готових свічок. Покупець обирає свічку, аромат, ґніт і кількість, кладе в кошик і оформлює замовлення.
- **B2B кастомізація** (`#b2b`) — свічки з власним дизайном для компаній, весіль і подій: конструктор (колір склянки, аромат, ґніт, напис, зображення, логотип, квіткові шаблони), приклади робіт, ціни за тиражем і запит на партію.

Розділ відкривається за адресою: `…/#b2b` або будь-який якір усередині B2B (`#konstruktor`, `#tsiny`, `#pryklady`) показує B2B, решта — магазин.

Сайт статичний: HTML, CSS і JavaScript без збірки. Його можна розмістити на GitHub Pages або на будь-якому звичайному хостингу.

## Структура

```
index.html                 розмітка сторінки
assets/css/style.css       стилі
assets/js/config.js        налаштування: товар, кольори, аромати, ціни, зона друку, адреса для заявок
assets/js/photos.js        шляхи до фото
assets/js/app.js           конструктор, ціни, заявки, чернетка
assets/img/site/           фото першого екрана, блоку для бізнесу, приклади
assets/img/works/          фото «Прикладів робіт»
assets/img/mockup/         фото склянки для конструктора (калібровані, див. нижче)
.nojekyll                  вимикає обробку Jekyll на GitHub Pages
```

## Публікація на GitHub Pages

1. Створіть новий репозиторій на GitHub (наприклад, `rdk-candle`).
2. Завантажте в нього **вміст** цієї папки, а не саму папку:
   - через браузер: **Add file → Upload files**, перетягніть усі файли й папки, натисніть **Commit changes**;
   - або через термінал:
     ```bash
     git init
     git add .
     git commit -m "Перша версія сайту"
     git branch -M main
     git remote add origin https://github.com/<ваш-акаунт>/rdk-candle.git
     git push -u origin main
     ```
3. У репозиторії відкрийте **Settings → Pages**. У полі **Source** оберіть **Deploy from a branch**, гілку `main`, папку `/ (root)` і натисніть **Save**.
4. За хвилину-дві сайт буде доступний за адресою `https://<ваш-акаунт>.github.io/rdk-candle/`.

**Власний домен.** У **Settings → Pages → Custom domain** вкажіть домен (наприклад, `candle.rdeco.com.ua`) і додайте у DNS запис `CNAME` на `<ваш-акаунт>.github.io`.

## Перегляд на своєму комп’ютері

Не відкривайте `index.html` подвійним кліком. У такому режимі браузер блокує частину функцій: прев’ю для заявки та збереження проєкту. Запустіть простий локальний сервер у папці сайту:

```bash
python3 -m http.server 8000
```

і відкрийте `http://localhost:8000`.

## Що налаштувати перед запуском

Усі дані, що можуть змінюватися, винесено в `assets/js/config.js`. Позначене `DEMO` — тимчасові значення.

| Що | Де в `config.js` | Зараз |
|---|---|---|
| Плашка «Демоверсія» | `showDemoNotice` | увімкнена |
| Розміри склянки й зони друку | `vessel` → `diameterMm`, `heightMm`, `printArea` | демонстраційні: Ø 80 мм, зона друку 56 мм по всьому колу |
| Кольори склянки | `colors` | прозора, чорна, біла + «інший колір під замовлення» |
| Аромати й ґноти | `scents`, `wicks` | ваш список ароматів; ґніт бавовняний або дерев’яний |
| Ціни | `pricing.tiers`, `pricing.quoteFromQty`, `pricing.approved` | 1 шт 800, 2–9 шт 500, 10–99 шт 300 грн, від 100 шт — індивідуальний розрахунок; показуються як орієнтовні, поки `approved: false` |
| Обертання свічки в конструкторі | `preview.autoSpin`, `degPerSec`, `resumeAfterMs` | увімкнене, 16°/с, відновлюється через 4 с після дії |
| Мінімальна кількість, строки | `order.minQty`, `order.leadTime` | не вказані |
| Контакти у футері | `contacts` | не вказані |
| Адреса для заявок | `order.endpoint` | `null`, заявки не надсилаються |

## Прийом заявок

GitHub Pages тільки показує сторінки, приймати дані він не вміє. Поки `order.endpoint` не заданий, сайт чесно пише «Заявку ще не надіслано» і пропонує зберегти пакет заявки (ZIP) або скопіювати її текст; для запиту на партію — скопіювати текст запиту. Повідомлення «Замовлення надіслано» не з’являється.

Щоб заявки приходили, потрібна невелика серверна функція: Cloudflare Workers, Netlify Functions, Vercel, власний сервер або вебхук Make/Zapier, що вміє приймати файли. Її адресу вкажіть у `order.endpoint`.

**Запит від сайту:** `POST`, `multipart/form-data`:
- `payload` — JSON заявки: контакти, кількість, колір склянки, аромат, ґніт, розрахунок ціни, структура дизайну (елементи з координатами в мм, кольорами, шрифтами, поворотом) і стан редактора;
- `files` — кілька файлів: оригінали завантажених зображень, `layout-print.png` (розгортка дизайну без мокапу, для виробництва) і `preview-mockup.png` (прев’ю на склянці для погодження).

**Відповідь функції:** JSON `{ "ok": true, "id": "номер заявки" }`. Будь-яку іншу відповідь сайт покаже як помилку, і покупець зможе зберегти заявку локально.

Функція може, наприклад, надіслати лист менеджеру з файлами, створити угоду в CRM або написати в Telegram. Для замовлень з магазину, заявок з конструктора й запитів на партію формат той самий, різниться поле `kind`: `shop`, `order` або `batch`. Замовлення з магазину надсилається без файлів: у `payload` є товари (`items`: назва, кількість, аромат, ґніт), контакти, місто й адреса доставки та розрахунок ціни.

## Магазин

- Товари задано в масиві `PRODUCTS` в `assets/js/app.js`: назва, опис, категорії (`floral`, `gift`, `love`) і фото (`photo`) або квітковий дизайн (`tpl`), який малюється на мокапі склянки й обертається в картці товару.
- Ціна за свічку береться з тих самих тарифів `pricing.tiers` і залежить від загальної кількості свічок у кошику; від `pricing.quoteFromQty` — індивідуальний розрахунок.
- Кошик зберігається в браузері покупця (localStorage). Доставку й оплату сайт не обіцяє: покупець вказує місто й відділення або адресу, а умови погоджуються під час підтвердження замовлення.

## Заміна фото

- **Фото сайту та приклади робіт.** Покладіть новий файл з тим самим ім’ям у `assets/img/site/` або `assets/img/works/`, або змініть шлях у `assets/js/photos.js`. Підписи й тексти прикладів — у масиві `WORKS` в `app.js`.
- **Фото склянки в конструкторі** (`assets/img/mockup/`) — це вирізане фото тари з картами тіней і відблисків. Їхні координати (центр і еліпси вінець, поверхня воску, ґніт) задано в `config.js` → `mockup.photo`. Під реальну тару їх треба переробити разом із калібруванням, інакше дизайн ляже на склянку неточно.

## Шаблони й колекції

- Квіткові ілюстрації намальовані у векторі в `app.js` (об’єкт `BOTANICA`), тому друкуються чітко в будь-якому розмірі. Шаблони, які бачить покупець, задано в масиві `FLORAL_TEMPLATES`, а «Готові колекції» — у `COLLECTIONS`.
- Шаблони з написами, на яких тримаються кнопки «Створити на основі цього дизайну» в «Прикладах робіт», лежать у `TEMPLATES` з позначкою `chip: false`. У рядку шаблонів конструктора вони не показуються.

## Що працює

- конструктор: колір склянки, аромат, ґніт, написи кількома шрифтами з українськими літерами, завантаження PNG/JPEG з перевіркою якості, переміщення, масштаб і поворот (зокрема дотиком на телефоні), шаблони, скасування дії, скидання, поворот свічки, розгортка зони друку;
- калькулятор ціни за кількістю;
- чернетка зберігається на пристрої покупця (IndexedDB);
- заявки на одну свічку, на партію й на готову колекцію з перевіркою полів;
- пакет заявки з окремим виробничим макетом і прев’ю;
- адаптивна верстка для телефонів, доступні підписи й контраст.

## Зовнішні ресурси

- шрифти Google Fonts (Lora, Manrope та шрифти для написів);
- бібліотека JSZip з cdnjs, щоб збирати ZIP-пакет заявки.
